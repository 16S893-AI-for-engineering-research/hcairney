# Presentation Plot

Write plotting scripts that produce legible, uncluttered figures for presentation slides.

## Required defaults

Unless the user requests otherwise:

- Use Python and Matplotlib.
- Treat `11.2 × 7` inches as the maximum size of the **entire figure canvas**, not the size of each subplot. Choose a smaller figure when appropriate, but never exceed either limit.
- Use these font sizes throughout the figure, including figures with subplots:
  - axis labels: 14 pt
  - axes titles and figure titles: 16 pt
  - legends: 12 pt
- Set presentation-related sizes explicitly rather than relying on the user's local Matplotlib defaults.
- Apply the same formatting consistently to every axes object in a multi-panel figure.

A suitable starting point is:

```python
import matplotlib.pyplot as plt

with plt.rc_context({
    "axes.labelsize": 14,
    "axes.titlesize": 16,
    "figure.titlesize": 16,
    "legend.fontsize": 12,
}):
    fig, ax = plt.subplots(figsize=(8, 5), constrained_layout=True)
    # Plot data and label the figure here.
```

For subplots, `figsize` still describes the whole figure:

```python
fig, axes = plt.subplots(
    2,
    2,
    figsize=(11.2, 7),
    constrained_layout=True,
)
```

## Legibility and visual design

- Prefer a simple composition that communicates one main point.
- Label axes with both the quantity and units when units are known, for example `Time (s)`.
- Use meaningful titles and legend labels; do not leave autogenerated labels in the final figure.
- Avoid redundant titles, legends, annotations, or repeated axis labels.
- Use colorblind-friendly colors and ensure important distinctions remain understandable when projected or viewed in grayscale. Combine color with line style or markers when useful.
- Ensure annotations and data do not overlap or get clipped.
- Use a light grid only when it helps viewers estimate values; do not let gridlines compete with the data.
- Remove unnecessary visual clutter, such as decorative effects, excessive minor ticks, and uninformative spines.
- Use adequate line widths and marker sizes for projection. As starting defaults, use lines of at least 2 pt and markers of at least 6 pt, adjusting for the figure and data density.
- Keep tick labels readable. Use 12 pt by default unless the user specifies another size.
- Prefer direct labeling over a legend when it is clear and does not crowd the plot.

## Layout and subplots

- Choose the subplot arrangement to preserve readable axes; do not shrink many panels into a single slide merely to fit them.
- Share axes where it improves comparison, but retain enough labels that each panel is understandable.
- Use `constrained_layout=True` by default. If it does not work for the requested plot, use another explicit layout adjustment such as `fig.tight_layout()`.
- Add short panel labels such as `(a)` and `(b)` when the panels need to be referenced in speech or accompanying text.
- Verify that titles, labels, legends, colorbars, and annotations fit inside the 11.2 × 7 inch canvas.
- Give colorbars readable labels and tick labels; their text follows the same sizing principles as axis text.

## Script quality and output

- Produce a complete, runnable script unless the user asks for a snippet.
- Separate data preparation from plotting when practical.
- Use the object-oriented Matplotlib API (`fig`, `ax`) rather than relying primarily on pyplot's implicit current axes.
- Use deterministic sample data by setting a random seed when a self-contained example requires randomness.
- Save with a tight bounding box and a white background unless transparency is requested:

```python
fig.savefig("figure.png", dpi=300, bbox_inches="tight", facecolor="white")
```

- Prefer a vector format such as PDF or SVG for line art and text when the slide workflow supports it. Use a high-resolution PNG for raster output or when compatibility is more important.
- Call `plt.show()` when interactive display is useful. Close figures in batch scripts that generate many outputs.

## Respect user requirements

Treat these instructions as defaults. Follow explicit user requirements for plotting library, dimensions, typography, style, file format, accessibility, or output behavior when they conflict with this guide. Do not change the meaning, scaling, or representation of the user's data solely for visual polish; clearly explain any transformation that affects interpretation.
