## What I added

This past week I have been working on setting up the deterministic policy gradient algorithm
I used previously with the RANS solver and use it with the LES solver. This has been a lot
of infrastructure.

## Why I added it

The RL in RANS workflow I outlined in the [week-05 dev-log](/src/content/dev-log/week-05.md)
has stalled because I ran into the issue that getting the RANS solver to converge with
non-uniform forcings applied. Rather than debugging the solver, I decided to move on to
the LES case. The RL algorithm was able to learn good results on the unforced RANS case
so I decided that this would be good enough to proceed.

## How I used the agent

I used the agent to plan the implementation which integrates the RL learner with the
LES solver. This required building up a local library with hooks into the solver which 
collects the data needed for training, validates it, and adds it to the replay. Then the
RL learner needs to use the data to perform updates to the actor and critic networks and
then publishes the next actor network used by the solver to collect the next episodes data.

The agent created a set of backlog tasks based on the implementation plan. Rather than letting
the agent just go to town on the backlog tasks, I proceeded to go through these one at a time.
For each task, I asked the agent to review the task and the existing code to make sure everything
is clear and that there weren't any decisons blocking implementation or that the agent would make
during implementation. Then the agent would implement and I would review the implementation.
The agent used the TDD skill in the actual implementation. However, I also requested specific
validation tests throughout the implementation to make sure that the changes were being implemented
appropriately. For example, any changes to the solver would be followed by a small smoke run with
the same overall setup as a previous simulation. The solver's resulting solution fields would be 
required to be identical to the previous baseline.
